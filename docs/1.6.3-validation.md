# 1.6.3 内置主题与连接修复：验证说明

日期：2026-09-18。基线：`2c86288`（1.6.2）。

## 故障证据与修复

同事日志中，`sky-breeze` 多次 `EXIT1`，但同一 WorkBuddy 5.5.6 会话的临时主题曾成功。两者都经过相同的 CodeDrobe 首次应用链，不能据此认定 Node 缺失或整个 CDP 不兼容。

从微软 winget 仓库的 Tencent.WorkBuddy/5.5.6 清单定位腾讯官方程序包，核对 SHA256 与腾讯 Authenticode 签名有效后仅解包分析，没有运行或安装此 WorkBuddy：

- 官方文件：`WorkBuddy-win32-x64-user-5.5.6.38337834-5f969292.exe`
- SHA256：`B1C61B8A0550012C3E9E2CCE4B2D566FB5BDB3283E97146B8808C3DCB1A571F4`
- 官方组件结构：`InputBox → .cr-input-box__main → .cr-input-container-wrapper → .cr-input-container → .cr-input-editor-host / .cr-input-toolbar`。
- 旧包首页强制检查 `input-slot > section`，项目输入区强制检查 `_mainArea_`。四个内置包在新结构均失败；自定义临时包没有这两条强制旧选择器，吻合日志中的差异。原始日志未保留底层错误，所以仍不能排除同事电脑同时有其他问题。

修复内容：

1. 保留旧选择器，同时加入新语义节点；不存在真正输入框仍拒绝应用，不移除必要校验。
2. 四个内置包新增共享的 5.5 输入框样式，输入外层负责底色，编辑区/工具栏内层透明。补齐聚焦、发送/禁用控件和原生偶奇填充图标。只改外观，不改布局、尺寸、滚动、点击或显示条件。
3. 只读预检查并行执行，主窗口通过后缩短空白附属窗口等待；验证阶段允许忽略消失的附属目标，但已安装/兼容窗口的验证失败仍阻止成功。零个合格主窗口不能通过。
4. CLI 输出有版本的结构化诊断。JS 和 Rust 分别使用静态错误码/检查项白名单，不保存异常原文、路径、页面标题、URL、CSS、截图或聊天内容。区分主题包读取/格式、组件不匹配、连接、请求超时、总超时和校验错误。
5. 自动保持遇到确定性故障暂停；瞬时连接错误保留最多三次有界重试。等待退避不再误报“重试已耗尽”，后续轮询不覆盖原始错误码；新 renderer 或用户重新开关自动保持可复位。删除重复失败日志。

## 未完成的现场验收

本轮没有启动/关闭/升级用户的 WorkBuddy 5.2.6，没有读取用户聊天，没有在同事的已登录 5.5.6 上操作。解包与浏览器协议测试不等于普通 Windows 账户完整安装、登录后的真实首页/项目/对话、重启保持及十分钟试用回退验收。新版保留候选标识，不能据这些测试宣称所有 5.5.6 环境必然通过。

现场只需要正常安装并从首页选择“晴空海风”应用。若已有 CDP 不必重启；否则由使用者保存工作并明确确认开启。验收应包含应用节点 1、恢复 0、输入/滚动/点击、重开切换器及 WorkBuddy 后自动保持；任何失败先记录新版静态错误码，不要求同事安装开发工具或改文件。
